# v2.6.1

本版本修复 SupJav 页面明确有完整资源、程序却可能报告探测失败的问题。SupJav 当前部分播放器不使用 `.m3u8` 后缀，而是把 HLS 主清单放在 `master.txt` 地址中；旧版只按文件后缀捕获，因而会漏掉这些有效资源。

## 修复

- 识别标准 `.m3u8` 以及 SupJav 使用的 `master.txt` HLS 主清单。
- 静态解析和 Chromium 捕获统一使用安全的 HLS 候选校验。
- 不再根据 TV、FST、ST、VOE 等服务器名称固定判断媒体类型，改为检查各服务器实际返回内容。
- 浏览器捕获时保留播放器请求的真实 Referer、Cookie 与 User-Agent，供画质探测和本机 HLS 转发继续使用。
- 初始导航返回验证状态时，等待页面完成渲染；只有最终页面出现同站点且准确匹配番号的结果才继续。
- 保持现有下载回退机制：按分辨率、码率、时长排序，首选失败后自动尝试下一条直链。

## 真实验证

- 使用 SupJav 的 `START-629` 完整播放清单进行在线探测。
- 成功识别 `1920×1080`、`2672571 bps`、`9922.967` 秒，并标记为有效完整 HLS。
- 本机 HLS 转发成功读取并重写 `master.txt` 清单，确认包含 1080p 档位。
- 同一番号的 MissAV 为 `1920×1080 / 4179 Kbps`，因此程序会正确保留 MissAV 作为更高码率首选。

## 兼容性

- 不增加配置项，不改变安装路径、媒体目录、Web 账号、端口或已完成任务。
- 现有用户可继续使用原一键更新命令升级。
- VPS 如果被 SupJav 完全拒绝访问，程序仍会保留明确的 HTTP 状态并继续尝试其他来源；本项目不绕过验证码、DRM、付费墙或访问控制。

## 测试

- Python 语法检查通过。
- 74 项自动化测试全部通过，覆盖 HLS 识别、画质排序、下载回退、HLS 转发、安装升级、Web 与媒体管理。
