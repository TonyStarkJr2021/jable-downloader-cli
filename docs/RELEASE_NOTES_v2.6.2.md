# v2.6.2

本版本修复 SupJav 在部分 VPS 上仍然探测失败的问题。SupJav 的旧查询参数搜索入口可能对数据中心网络返回 HTTP 403，而路径式公开搜索入口仍可正常使用；旧版静态解析和 Chromium 回退没有完整尝试这些入口，FC2 的浏览器回退还会丢失站点要求的专用搜索写法。

## 修复

- SupJav 优先尝试 `/search/番号/` 路径式公开搜索入口，并保留 `/?s=番号` 作为兼容回退。
- 单个搜索入口返回 403、跳转异常或没有结果时继续尝试其余入口，不再立即结束 SupJav 探测。
- 普通番号与 FC2 番号的静态解析、Chromium 回退共用相同的搜索入口生成逻辑。
- FC2 优先使用 SupJav 接受的 `FC2PPV 数字` 写法，并保留规范的 `FC2-PPV-数字` 作为备用。
- 并行浏览器日志中的 HTTP 状态增加 Jable、MissAV 或 SupJav 来源名称，便于准确判断失败站点。

## 真实验证

- `START-629`：SupJav 成功解析三条完整 HLS，最佳为 `1920×1080 / 2684340 bps / 9923 秒`。
- `FC2-PPV-4968930`：SupJav 成功解析两条完整 HLS，最佳为 `1920×1080 / 2858116 bps / 4485 秒`。
- 同一 FC2 番号的 MissAV 资源为 `1280×720 / 1773 Kbps`，修复后画质排序会优先选择 SupJav 1080p。
- 两个番号均完成详情页、播放器服务器、主清单、分辨率、码率、时长和有效性在线检查。

## 兼容性

- 不增加或删除配置项。
- 更新保留媒体目录、Web 账号、端口、Chromium profile、已完成列表及全部媒体。
- 不修改 Jellyfin、MetaTube、Docker、挂载点或外部 `update-media` 命令。
- 若 VPS 被 SupJav 整站拒绝访问，程序仍会继续尝试 Jable、MissAV 及后续回退；本项目不绕过验证码、DRM、付费墙或访问控制。

- 安装、更新、卸载、Web、媒体分类、HLS 转发和下载候选回退测试全部通过。
